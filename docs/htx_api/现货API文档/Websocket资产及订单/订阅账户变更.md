# accounts.update#${mode} (订阅账户变更)

> 文档来源：https://www.htx.com/zh-cn/opend/newApiPages/?id=7ec4927d-7773-11ed-9966-0242ac110003

## 接口信息
| 项目 | 内容 |
|---|---|
| 请求类型 | - |
| 是否验签 | 否 |
| 接口权限 | 读取 |
| 接口描述 | 订阅账户的余额更新。 |

## 请求地址
| 环境 | 地址 |
|---|---|
| 线上环境 | `wss://api.huobi.pro/ws/v2` |
| 线上环境（aws客户首选） | `wss://api-aws.huobi.pro/ws/v2` |

## 请求参数
| 参数 | 数据类型 | 是否必填 | 描述 |
|---|---|---|---|
| mode | string | 否 | 模式<br>0:仅当账户余额变动时推送 1:在账户余额发生变动或可用余额发生变动时均推送且分别推送。 2:在账户余额发生变动或可用余额发生变动时均推送且一起推送。 |

**请求参数说明**：<br/>订阅示例<br/>1、不填mode：<br/>accounts.update<br/>仅当账户余额变动时推送；<br/>2、填写mode=0：<br/>accounts.update#0<br/>仅当账户余额变动时推送；<br/>3、填写mode=1：<br/>accounts.update#1<br/>在账户余额发生变动或可用余额发生变动时均推送且分别推送。<br/>4、填写mode=2：<br/>accounts.update#2<br/>在账户余额发生变动或可用余额发生变动时均推送且一起推送。<br/>注：无论用户采用哪种模式订阅，在订阅成功后，服务器将首先推送当前各账户的账户余额与可用余额，然后再推送后续的账户更新。在首推各账户初始值时，消息中的changeType和changeTime的值为null。<br/>

## 请求示例
```json
{
"action":"sub",
"ch":"accounts.update"
}
```

## 响应示例
```json
{
"action":"sub",
"code":200,
"ch":"accounts.update#0",
"data":{}
}
```

## 推送数据
| 参数 | 数据类型 | 是否必填 | 描述 |
|---|---|---|---|
| currency | string | 否 | 币种 |
| accountId | long | 否 | 账户ID |
| balance | string | 否 | 账户余额（仅当账户余额发生变动时推送） |
| available | string | 否 | 可用余额（仅当可用余额发生变动时推送） |
| changeType | string | 否 | 余额变动类型，有效值：order.place(订单创建)，order.match(订单成交)，order.refund(订单成交退款)，order.cancel(订单撤销)，order.fee-refund(点卡抵扣交易手续费)，margin.transfer(杠杆账户划转)，margin.loan(借币本金)，margin.interest(借币计息)，margin.repay(归还借币本金币息)，deposit (充币）, withdraw (提币)，other(其他资产变化) |
| accountType | string | 否 | 账户类型，有效值：trade, loan, interest |
| changeTime | long | 否 | 余额变动时间，unix time in millisecond |
| seqNum | long | 否 | 账户变更的序号 |
